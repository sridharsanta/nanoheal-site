The difference

Scripts have to go looking for a problem. Nanoheal is told.

Every operating system already announces its own failures — event logs, service states, crashes, the error the user is staring at. Script-based automation ignores that channel and rebuilds detection from scratch. Nanoheal listens to it.

Script-based automation

Write code, ship it, hope it holds.

The prevailing model across the category.

  • An engineer writes a script.PowerShell, Bash, shell — new code for every symptom and every variation of it.
  • It is pushed to the fleet.Payloads accumulate. Every new fix adds weight to every endpoint.
  • It has to keep polling.To catch a symptom, the script stays resident and re-checks on an interval — burning CPU, memory and battery on machines that are mostly fine.
  • Then the estate moves.A patch, a policy, a new OS build — and the script fails silently until somebody notices.

The real cost: detection you paid to build, and pay again to run, on every device, all the time.

Nanoheal · symptom-triggered

The symptom is the trigger. No script exists.

Detection is free, because the OS already did it.

  • The OS reports the symptom.An event log entry, a service failure, a crash, an error surfaced to the user. Nanoheal understands it in the form the OS already produces.
  • Intelligence reads the context.The semantic context layer resolves what this symptom means here — against DEX signals, your SOPs, ITSM history, CMDB and policy.
  • It selects a capability, not code.The engine exposes an API for what a device can actually do. Intelligence picks the right capability and supplies its parameters from the knowledge base.
  • The engine executes it.Sealed, versioned, guardrailed. Knowledge is what ships — small, portable, valid on every OS build the engine supports.

The result: no script authored, no payload bloat, nothing probing in the background — and a fix that arrives the moment the symptom does.

The engine

The intelligence doesn't write code. It chooses from what the device can already do.

Device operations are exposed as a governed capability API. The knowledge layer describes what to do; the engine owns how. That separation is why a fix is kilobytes of knowledge instead of a codebase you maintain.
